?? WHAT THE POLLING DATA TABLE DOES
????????????????????????????????????????????????????????????????????????

RECORDS every polling activity:

1. POLLING REQUEST SENT
   ?? When provider sends poll request to NPHIES
   ?? Stores: Provider ID, message types, request timestamp
   ?? Links to: TaskRequest table

2. POLLING RESPONSE RECEIVED
   ?? When provider receives response from NPHIES
   ?? Stores: Response status, message count, response timestamp
   ?? Links to: TaskResponse table

3. COMPLETE AUDIT TRAIL
   ?? Processing status (pending ? processing ? completed)
   ?? Cycle status (in-progress ? completed ? timed-out)
   ?? Error tracking (error code, message)
   ?? Retry tracking (retry count, max retries)
   ?? Performance metrics (duration in milliseconds)

4. COMPLIANCE & AUDITING
   ?? Full FHIR Bundle JSON (request & response)
   ?? IP address of requester
   ?? Acknowledgment tracking
   ?? Timestamp for every operation


????????????????????????????????????????????????????????????????????????
?? POLLING RECORD TABLE SCHEMA
????????????????????????????????????????????????????????????????????????

TABLE: PollingRecords
?????????????????????

IDENTIFIERS & TRACKING:
  • Id (PK): Unique database identifier
  • PollingRecordId: Human-readable record ID
  • ProviderId (FK): Links to Organizations table

REQUEST INFORMATION:
  • RequestTaskId: FHIR Task ID sent to NPHIES
  • TaskRequestId (FK): Link to TaskRequest table
  • RequestedMessageTypes: Types requested (comma-separated)
  • RequestSentAt: When request was sent
  • RequestBundleJson: Full FHIR Bundle (for audit)

RESPONSE INFORMATION:
  • ResponseTaskId: FHIR Task ID received from NPHIES
  • TaskResponseId (FK): Link to TaskResponse table
  • ResponseStatus: ok | error | partial-success | timeout
  • ResponseReceivedAt: When response was received
  • ResponseBundleJson: Full FHIR Bundle (for audit)

MESSAGE TRACKING:
  • MessagesReceived: Count of messages in response
  • ReceivedMessageTypes: Types received (comma-separated)

PROCESSING STATUS:
  • ProcessingStatus: pending | processing | completed | failed | acknowledged
  • CycleStatus: in-progress | completed | timed-out | failed
  • IsAcknowledged: Has provider acknowledged?
  • AcknowledgedAt: When acknowledged

PERFORMANCE METRICS:
  • DurationMs: Total time from request to response (milliseconds)
  • HttpStatusCode: HTTP response status (200, 400, 500, etc.)

ERROR HANDLING:
  • ErrorMessage: Description of any error
  • ErrorCode: Machine-readable error code

RETRY MANAGEMENT:
  • RetryCount: How many times already retried
  • MaxRetries: Maximum retries allowed
  • NextRetryAt: When next retry is scheduled

SECURITY & AUDIT:
  • SourceIpAddress: IP address of requesting system
  • RequestSourceId: Identifier of requesting provider system
  • Notes: Free-form notes for additional context
  • CreatedAt: Record creation timestamp
  • UpdatedAt: Last modification timestamp
  • IsActive: Soft delete flag
